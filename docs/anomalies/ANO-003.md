# ANO-003 — Champs des formulaires d'administration sans aucun libellé

| Champ | Valeur |
|---|---|
| **ID** | ANO-003 |
| **Type** | IHM (accessibilité) |
| **Sévérité** | Majeur |
| **Module** | `/admin` — onglets Joueurs (5 champs), Équipes (4), Poules (2), Comptes (1) ; `/matches` — filtre de statut |
| **Environnement** | Firefox 160.0.1, Linux, commit `a0d25ca` |
| **Test associé** | TSP44 (exigence SP44 — WCAG 2.1 critères 1.3.1, 3.3.2, 4.1.2), constaté pendant TSP51-02 ; impacte TSP59 |
| **Pré-requis** | Connecté en administrateur (`admin@padel.com`) |

## Étapes de reproduction
1. Se connecter en administrateur, ouvrir http://localhost:5173/admin, onglet **Joueurs**.
2. Observer le formulaire de création de joueur.
3. Saisir un caractère dans le champ « Prénom ».
4. Ouvrir l'onglet **Équipes** et observer les listes déroulantes.

## Résultat attendu
Chaque champ a un **libellé visible et persistant**, relié au champ (`<label for>`), qui reste
affiché pendant la saisie (WCAG 3.3.2).

## Résultat obtenu
Aucun `<label>` dans `AdminView.vue` (12 champs). Les champs texte n'ont qu'un `placeholder`
(« Prénom », « Nom », « Licence (LXXXXXX) »…) qui **disparaît dès la première saisie** :
l'utilisateur ne sait plus quel champ il remplit. Les listes déroulantes (joueurs d'une équipe,
poule, sélection de joueur pour un compte, équipes d'une poule) n'ont **aucun nom**, ni visible ni
accessible. Même constat pour la liste « filtre de statut » de `/matches`.

## Preuve
Code : `frontend/src/views/AdminView.vue` lignes 150-154 (champs Joueurs), 183-192 (Équipes), 219-220 (Poules), 244 (Comptes) : aucun `<label>`, uniquement des `placeholder` ; `MatchesView.vue` ligne 158 (filtre de statut).

## Correction suggérée
Ajouter un `<label for>` visible au-dessus de chaque champ, comme sur `/matches`, en gardant le
`placeholder` uniquement comme exemple de format.

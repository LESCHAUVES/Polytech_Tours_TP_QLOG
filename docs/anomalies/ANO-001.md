# ANO-001 — Bordure des champs de saisie insuffisamment contrastée

| Champ | Valeur |
|---|---|
| **ID** | ANO-001 |
| **Type** | IHM (accessibilité) |
| **Sévérité** | Majeur |
| **Module** | Tous les champs utilisant la classe `.input` (`frontend/src/style.css`) : `/login`, `/profile`, `/change-password`, `/matches`, `/admin` (4 onglets) |
| **Environnement** | Firefox 160.0.1, Linux, commit `a0d25ca` |
| **Test associé** | TSP51-01, TSP51-02 (exigence SP51 — WCAG 2.1 critère 1.4.11, niveau AA) |
| **Pré-requis** | Visiteur non connecté, application lancée après `python seed.py` |

## Étapes de reproduction
1. Ouvrir http://localhost:5173/login.
2. Clic droit sur le champ **Email** → *Inspecter* → onglet *Calculé* → relever `border-top-color`.
3. Sélectionner le conteneur `<div class="card">` → relever `background-color`.
4. Calculer le ratio avec WebAIM Contrast Checker.

## Résultat attendu
Le contour d'un champ de saisie (composant d'interface) a un contraste **≥ 3:1** avec le fond
adjacent (WCAG 1.4.11), pour que les malvoyants repèrent où saisir.

## Résultat obtenu
Bordure `rgb(209, 213, 219)` (`#d1d5db`, Tailwind `gray-300`) sur fond `rgb(255, 255, 255)` :
**1,47:1**. Le champ vide est quasiment invisible pour un utilisateur malvoyant.

## Preuve
Mesure relevée dans l'inspecteur de Firefox (onglet *Calculé*) : `border-top-color: rgb(209, 213, 219)` sur l'`<input>`, `background-color: rgb(255, 255, 255)` sur `.card` ; WebAIM Contrast Checker : **1.47:1**.
Code : `frontend/src/style.css`, classe `.input` (`border-gray-300`).

## Correction suggérée
Dans `frontend/src/style.css`, classe `.input` : remplacer `border-gray-300` par
`border-gray-500` (`#6b7280`, 4,83:1 sur blanc).

# ANO-006 — Messages d'erreur des formulaires admin affichés loin des champs concernés

| Champ | Valeur |
|---|---|
| **ID** | ANO-006 |
| **Type** | IHM (accessibilité) |
| **Sévérité** | Mineur |
| **Module** | `/admin` (4 onglets) ; `/matches` (formulaire de création de match) |
| **Environnement** | Analyse du code, commit `a0d25ca` — à confirmer avec une loupe d'écran à 300 % |
| **Test associé** | TSP54-02 (exigence SP54) ; lié à TSP45 (annonce des messages, WCAG 3.3.1) |
| **Pré-requis** | Connecté en administrateur |

## Étapes de reproduction
1. Se connecter en administrateur, ouvrir http://localhost:5173/admin, onglet **Joueurs**.
2. Activer une loupe d'écran à 300 % centrée sur le formulaire.
3. Remplir le formulaire avec la licence `L123` et cliquer sur **Ajouter**.

## Résultat attendu
Le message d'erreur s'affiche **à côté du champ en erreur** (Licence), visible dans la zone
agrandie, et le champ est signalé comme invalide.

## Résultat obtenu
Le message est affiché dans un bandeau unique **en haut de la page**, sous les onglets
(`AdminView.vue` ligne 143), hors de la zone agrandie : l'utilisateur de loupe ne le voit pas
et ne sait pas quel champ corriger. Le champ Licence n'est pas mis en évidence. Même schéma sur
`/matches` (bandeau au-dessus du formulaire, `MatchesView.vue` ligne 170).

## Preuve
Code : `frontend/src/views/AdminView.vue` ligne 143 et `MatchesView.vue` ligne 170 (bandeau d'erreur unique placé avant les formulaires).

## Correction suggérée
Afficher le message sous le champ concerné (`aria-describedby` vers le message,
`aria-invalid="true"` sur le champ) et déplacer le focus sur le premier champ en erreur.

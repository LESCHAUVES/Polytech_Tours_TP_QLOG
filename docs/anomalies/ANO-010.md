# ANO-010 — Messages d'erreur et de succès non annoncés aux lecteurs d'écran

| Champ | Valeur |
|---|---|
| **ID** | ANO-010 |
| **Type** | IHM (accessibilité) |
| **Sévérité** | Majeur |
| **Module** | Tous les formulaires : `/login`, `/change-password`, `/profile`, `/matches`, `/admin` |
| **Environnement** | Analyse du code, commit `a0d25ca` — à confirmer avec un lecteur d'écran (NVDA / Orca) |
| **Test associé** | TSP59-02, 06, 07, 08 (exigence SP59) ; TSP45 (WCAG 4.1.3, 3.3.1) |
| **Pré-requis** | Lecteur d'écran actif |

## Étapes de reproduction
1. Activer un lecteur d'écran et ouvrir http://localhost:5173/login.
2. Saisir `joueur@padel.com` / `faux` et valider.
3. Écouter ce qui est annoncé.

## Résultat attendu
Le message « Mot de passe incorrect » et le nombre de tentatives restantes sont lus
automatiquement (zone `role="alert"` ou `aria-live`), et le champ est marqué invalide
(`aria-invalid`, `aria-describedby`).

## Résultat obtenu
Le frontend ne contient **aucun attribut ARIA** (`grep "aria-\|role="` sur `src/` : 0 résultat).
Les messages (`data-cy="login-error"`, `attempts`, `error`, `success`, `admin-error`,
`match-error`) sont de simples `<p>` insérés dans la page : ils ne sont pas annoncés et
l'utilisateur aveugle ne sait pas que la connexion a échoué ou que l'enregistrement a réussi.

## Preuve
Analyse du code : recherche `grep -rnE "aria-|role=" frontend/src` → 0 résultat.

## Correction suggérée
Ajouter `role="alert"` sur les messages d'erreur et `role="status"` (ou `aria-live="polite"`)
sur les messages de succès ; relier chaque message à son champ par `aria-describedby`.
